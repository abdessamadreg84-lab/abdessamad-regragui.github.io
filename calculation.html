CALCULATION

Don't calculate moves.
Calculate change.

A move is only the beginning of a calculation. The real object is the resulting state, the relations that changed, and what the new position allows.

THE BASIC TRANSFORMATION

A chess position is a state.

A position contains more than the locations of the pieces. It contains the relevant relationships between them: occupancy, reach, attacks, supports, constraints, blocks, duties, dependencies, and available possibilities.

STATE₀ → MOVE → STATE₁

Calculation is the projection of this transformation through its consequences.

THE REAL OBJECT

What changes because the piece moved?

A beginner may look at a move and primarily register the destination square.

A relational calculation asks what the move does to the entire position.

MOVE → RESULTING STATE → NEW RELATIONS

Opened

Which line, square, or route became available?

Removed

Which piece, defender, blocker, or restriction disappeared?

Created

Which new attack, support, threat, or dependency appeared?

REACH MUST BE REBUILT

The old position is no longer the current position.

Once a meaningful change occurs, the previous reach map is partly obsolete. A piece that was blocked may now be active. A defended square may become undefended. A line may open. A new counterattack may appear.

OLD POSITION → CHANGE → NEW REACH MAP

This is why calculation is not simply remembering a sequence of moves. Each meaningful state has to be read again.

THE CALCULATION LOOP

See. Change. Reconstruct. Read.

SEE CURRENT STATE
↓
MAKE A CANDIDATE CHANGE
↓
RECONSTRUCT THE NEW STATE
↓
READ THE NEW RELATIONS
↓
SEE THE OPPONENT'S RESPONSE
↓
UPDATE THE MODEL

The process then repeats from the new state.

01 · REACH

What can reach what?

Start with the relationships that can actually exist in the current position.

REACH = AVAILABLE INTERACTION

Look at lines, attacks, supports, movement possibilities, escape squares, and routes through the current occupancy.

The question is not simply what a piece theoretically does. It is what it can actually reach here.

02 · OCCUPANCY

What is actually there?

Before projecting a change, account for the pieces and squares that make the current position what it is.

REACH + OCCUPANCY → CURRENT FUNCTION

Occupancy can create support, attack, obstruction, protection, tactical targets, or restrictions.

03 · CONSTRAINT

What is stopping the desired relation?

A useful calculation often becomes clearer once the obstacle is identified.

CAPABILITY → CONSTRAINT → LIMITED EXPRESSION

The obstacle might be a blocker, defender, king safety rule, occupied square, tactical duty, or another dependency.

04 · FORCE

What can the relation do?

Once a relation is identified, ask what it can change.

RELATION → FORCE → POSSIBLE CHANGE

Can it push? Pull? Redirect? Release? Create tension? Block something?

This shifts calculation from naming patterns toward understanding their function.

05 · TENSE

Is the force active now or only after a change?

Active

The relation can currently express itself.

Conditional

The relation becomes available only if a state transformation occurs.

CURRENT FORCE ≠ FUTURE FORCE

This distinction prevents possible tactical ideas from being mistaken for current facts.

06 · RESULTANT

What would the interaction actually produce?

Do not stop at the intention of the move. Follow the interaction.

FORCE → INTERACTION → RESULTANT

The resultant could be a capture, opened line, removed defender, restriction, discovered attack, changed duty, escape square, or another structural transformation.

07 · CHANGE

What would actually be different?

This is the central calculation question.

What changed because of the move?

Before

What could reach what? What was blocked? Who defended what? Which duties existed?

After

Which of those relationships disappeared, appeared, strengthened, weakened, opened, or changed direction?

08 · NEW REACH

What does the new position allow?

After the transformation, return to the first question.

CHANGE → NEW STATE → NEW REACH

The cycle is recursive. Every meaningful state becomes the starting point for the next calculation.

THE COMPLETE LOOP

Calculation is recursive.

REACH → OCCUPANCY → CONSTRAINT
→ FORCE → TENSE → RESULTANT
→ CHANGE → REACH

The final step returns to reach because the new position has a different relational structure.

THE OPPONENT

The opponent is part of the model.

Your move changes the opponent's available possibilities. Their response then changes the state again.

MY MOVE → OPPONENT'S AVAILABLE CHANGES → NEW STATE

Calculation therefore cannot be only a projection of your own actions. It must include another agent who can transform the resulting position.

BRANCHING

The future is conditional.

A candidate move creates a new state. From that state, the opponent may have several meaningful responses. Each response produces another state.

STATE₀
↓
MY MOVE
↓
STATE₁
↙ ↓ ↘
RESPONSE A · RESPONSE B · RESPONSE C

Calculation does not require exploring every theoretical branch. Purpose and relevance determine which transformations deserve attention.

DIRECTION · OBSTACLE · MECHANISM

Purpose tells calculation where to look.

Direction

Where do I want the position to go?

Obstacle

What prevents that desired state?

Mechanism

What change could remove or overcome the obstacle?

PURPOSE → DIRECTION → OBSTACLE → MECHANISM

PREDICTION

Calculation is prediction through changing states.

Prediction in chess is not simply guessing the opponent's next move. It is projecting what the current position will allow after one or more transformations.

CURRENT STATE → POSSIBLE TRANSFORMATION → FUTURE STATE

A useful question is:

What will this position allow?

And when considering the opponent:

What will he see?

VISUAL CALCULATION

Calculation does not require move names.

The framework does not require calculation to be verbal. A player may represent future positions visually, spatially, relationally, symbolically, or through combinations of these.

CURRENT STATE → TRANSFORMATION → PROJECTED STATE

The move label can be secondary. The important thing is the changed state and the relationships inside it.

FROM READING TO CALCULATION

The same general operation appears in both domains.

Reading

WORDS → RELATIONS → MODEL

The reader uses the model to infer what is hidden, predict what comes next, and update it.

Chess

PIECES → RELATIONS → POSITION

The player transforms the position, projects the consequences, and reconstructs the new relations.

SEE → RELATE → MODEL → PROJECT → UPDATE

THE CORE OF CALCULATION

See the difference.
See the consequence.
See the direction.

Then see what will happen here.

About the framework

This is a functional framework for organizing chess calculation. It is not presented as a literal description of neural architecture or as a replacement for established chess theory, calculation methods, or analysis.
